# Relationship Compass v1 需求规格

> 状态:已确认(2026-09-12 讨论共识)。
> 术语以 `CONTEXT.md` 为准;架构决定见 `docs/adr/0001`、`docs/adr/0002`。

## Problem Statement

我一直想持续维护重要的人脉,但"维持关系"这件事目前完全依赖我的记忆:谁该联系了、上次聊了什么、多久没见了,散落在脑子、聊天记录和备忘录里。结果是——重要的人常常是在"已经很久没联系"之后才被我想起来,关系在不知不觉中变冷。通讯录只记联系方式,不懂"节奏";待办工具不懂"人"。我需要的不是又一个通讯录,而是一个能替我发现"这段关系该浇水了"的东西。

## Solution

一个只服务我一个人的本地 Web 工具:

- 打开它,首屏就是一句话的答案——**这周该主动联系谁**(逾期的人置顶,加上未来 7 天内到期的人);
- 联系完,顺手记一笔("已联系" + 一句话);记录后清单立刻更新;
- 欠得久了,它不等我打开——通过 macOS 系统通知主动来找我;
- 所有数据只在我自己的 Mac 上,备份就是拷贝一个文件。

它刻意做小:不做账号、不做云、不做导入、不做关系网——只把"维持关系"变成一份**每周有节奏、且可以被清空**的清单。

## User Stories

**清单与判定**

1. 作为唯一使用者,我希望打开应用就看到"本周清单",这样我不需要靠记忆决定今天该联系谁。
2. 我希望逾期的人永远出现在清单最前面,并按"欠得最久"排序,这样我没法假装他们不存在。
3. 我希望清单同时包含未来 7 天内到期的人,这样我可以提前安排这一周。
4. 我希望没有任何互动记录的联系人直接出现在清单里并标注"还没联系过",这样我刻意加进来的人不会被遗忘。
5. 我希望清单里每个人都能看到 TA 上榜的依据(上次联系时间 + 节奏,如"3 周没联系 · 希望每 2 周"),这样我明白 TA 为什么站在我面前。
6. 我希望逾期的人不会因为时间流逝自动消失——只有"记录一次互动"或"延后 / 改节奏"能让 TA 离开清单,这样清单不会欺骗我。

**记录互动**

7. 我希望一键记录"已联系",并能附一句话,这样记录成本低到不会阻止我坚持。
8. 我希望记录之后清单立刻更新(TA 离队或位置后移),这样我能获得即时反馈。
9. 我希望记录不问方向——对方主动联系我也算一次来往,这样我不用为每次互动纠结"谁先发起"。
10. 我希望在联系人详情页看到完整的互动流水(日期 + 那句话),这样我见面前能快速回忆我们聊过什么。
11. 我希望可以修正或删除记错的互动,这样误操作不会污染判定。

**联系人**

12. 我希望手工新增联系人(姓名必填;备注、节奏可选),这样我能把想维护的真人一个个放进来。
13. 我希望给每个联系人写一段自由备注(TA 是谁、怎么认识的、在意什么),让工具成为我的外部记忆。
14. 我希望随时编辑姓名与备注,这样信息保持最新。
15. 我希望每个联系人有联系节奏档(1 周 / 2 周 / 1 个月 / 3 个月 / 6 个月),新增时默认 1 个月,这样设置只需点一下。
16. 我希望有一个全部联系人的总览列表,这样我能一眼看到我在维护哪些人。
17. 我希望删除误加的联系人(带一次确认),这样错误条目能被清掉。

**延后**

18. 我希望把某个联系人"延后"到指定日期,延后期间 TA 从清单消失,这样清单不会变成"愧疚堆"。
19. 我希望看得到"正在延后"的人以及他们归来的日期,这样我知道他们没有被弄丢。
20. 我希望延后到期时 TA 自动回到清单,不需要我手动恢复。
21. 我希望在联系人详情里随时取消延后或改期。

**节奏调整**

22. 我希望随时调整某人的节奏档,清单立即按新节奏重算,这样名单始终反映我的真实意图。

**提醒**

23. 我希望有一个本机定时任务,在到期时通过 macOS 系统通知告诉我"该联系 X、Y、Z",这样我不需要记得打开它。
24. 我希望没有到期者时通知保持安静,这样提醒不会被训练成噪音。
25. 我希望点击通知能直接打开应用并落在清单上。
26. 我希望一条命令完成安装:启动本机服务 + 注册提醒任务。

**数据与运行**

27. 我希望所有数据都保存在本机的一个 SQLite 文件里,备份就是拷贝这一个文件。
28. 我希望重启浏览器或电脑之后,一切数据完好无损。
29. 我希望不需要注册、登录或密码,打开即用。
30. 我希望应用不联网也能完整工作(数据不出本机)。
31. 我希望应用第一次启动时预置一批假数据(假联系人 + 假互动),让我立刻看到完整效果。
32. 我希望之后能一键清除假数据、换成真人(手工录入),不残留任何假信息。

## Implementation Decisions

- **产品形态(ADR-0001)**:单用户、本地优先;无账号、无多租户、无分享;数据只存本机;不部署服务器。已知代价:离开这台 Mac 看不到清单;未来若要做移动端,需要一次明确的数据迁移。
- **技术栈(ADR-0002)**:pnpm + TypeScript;前端 Vite + React;后端是极简的本机 Node HTTP 服务;数据为 SQLite 单文件,使用 Node 内置 `node:sqlite`(零原生依赖);数据文件位于 macOS Application Support 目录。界面语言:中文。
- **提醒机制**:安装一个 launchd 定时任务;任务读取本机数据、按"本周清单"判定发送系统通知;清单为空则不发。
- **数据模型(领域词汇)**:
  - **联系人**:姓名、备注(自由文本)、联系节奏(受控枚举,默认 1 个月)、延后至(可空日期);
  - **互动**:引用一个联系人、发生日期、可选一句话;
  - **上次联系时间**不落库、不可手工编辑,由该联系人的互动流水推导。
- **判定规则(产品大脑,单一口径)**:到期 = 上次联系时间 + 联系节奏;本周清单 = 逾期者(按欠得最久降序)在前,其后是未来 7 天内到期者;逾期者不自动消失;延后中的联系人不参与判定,直到"延后至"当天;从未有互动者视为立即到期并标注"还没联系过"。所有日期按本机本地日期计算。
- **术语约束**:`CONTEXT.md` 是本项目领域词汇的唯一出处(联系人 / 关系 / 互动 / 联系节奏 / 上次联系时间 / 本周清单 / 逾期 / 延后)。其中"互动"明确为**不分方向**的来往;"关系"明确为"你与某个联系人的状态",**不含**联系人之间的关系网。
- **数据形态**:SQLite 单文件;不使用浏览器存储(清缓存即失、提醒任务读不到);数据文件不放进 git 仓库。
- **启动与安装**:一条命令启动本机服务(浏览器访问 localhost);另有安装/卸载命令管理 launchd 提醒任务。

## Testing Decisions

- **好测试的定义**:只验证外部行为——给定(联系人集合 + 互动集合 + "今天"),输出确定的清单判定结果;不测内部实现、不测 UI 结构。
- **测试 seam(尽可能少,首选 1 个)**:
  1. **判定逻辑 seam(唯一必需)**:把"本周清单"的计算暴露为一个纯函数——输入:联系人集合、互动集合、今天日期;输出:分类结果(逾期[含欠期] / 7 天内到期 / 未联系过 / 延后中 / 不在清单)。全部单元测试打在这一个 seam 上,覆盖:无互动;恰好到期与差一天的边界;逾期排序;延后中与延后到期;五个节奏档;跨月末与跨年日期。
  2. **存储 seam(仅在需要时)**:"写入互动后,该联系人的上次联系时间随之更新"这类往返完整性。默认不铺开,能不建就不建。
- **验收清单(v1 "做完"的定义;交付时附 5 分钟手动走查)**:
  - 首屏即本周清单:预置假数据后,第一眼就能看到 2~3 个逾期者置顶,其后是 7 天内到期的;
  - 一键记录互动后,清单与详情页即时更新;互动流水可见、可修正;
  - 手工新增/编辑联系人(含备注、节奏档、延后)全部可用;
  - 延后的人从清单消失、联系人页可见、到期自动回归;
  - 系统通知能按判定发出;无欠账时保持安静;
  - 一条命令启动服务;重启浏览器与电脑后数据完好;
  - 全部数据只在本机 SQLite 文件内。
- **明确不做**:UI 自动化 / e2e(Playwright 等)、通知脚本的自动化测试、视觉对比测试。理由:v1 的失败模式在"产品是否有用",不在"界面像素";测试预算集中在判定逻辑。

## Out of Scope

- 账号 / 登录 / 分享 / 多用户;
- 服务器部署、云端数据、移动端访问与多设备同步;
- 真实批量导入(CSV、系统通讯录)与半自动采集(日历、消息、通话记录);
- 联系人之间的关系网、引荐路径;
- 自由输入式的节奏定制、自定义通知时间表;
- 多语言(仅中文);
- UI 自动化测试。

## Further Notes

- **验证实验(交付后执行)**:把假数据换成 **8~12 个真心想维护的真人**(手工录入),试用 **2 周**。
  - 成功信号(≥2):有互动是"因为清单"发生的;通知会被看;开始主动记备注;用过延后或改过节奏。
  - 失败信号(≥2):两周内没有因清单联系过人;通知被无视或关闭;打开是负担感;发现备忘录更顺手。
  - 两周后:成功 → 讨论 v1.5 方向(真实导入 / 体验打磨);失败 → 先分清"意愿问题"还是"摩擦问题",**不以"加功能"回应失败**。
- **仓库事项**:README 需从 "macOS app" 改写为 Web 定位;建议将 GitHub 仓库名去掉 `-macos` 后缀(需人工在网页操作)。
